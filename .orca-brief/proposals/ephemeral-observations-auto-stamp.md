# 候選:易逝的觀測由工具自動蓋章,不寫成給人遵守的規則

來源:專案 A(`llm_learning-cards`)技術顧問,2026-09-12。
**尚未批准,素材。** 這是**行為變更**,若要做是 1.7.0。

## 推導鏈(三則往返的終點,記下來因為過程就是論證)

1. 專案 A 提「逾時理由要附 `uptime`」(已收進 1.6.0 的 `docs/07-practices.md` (am))。
2. 專案 A 協調者在**寫那條規則的同一個 commit 裡**把「今天空機 load < 1」寫進註解而**沒量**,
   真跑是 12.47(見 `self-diluting-mechanism.md` 檢查點 4)。
3. ARIA 標出技術事實:**`load average` 是衰減平均,過去式查不到——記錄的機會只存在於那一瞬間。**
4. 專案 A 把最後一步推完:**如果一個值只在那一瞬間可記,那它就不該交給紀律去記。**

## 論證

> 要求人在**正確的瞬間**做**正確的事**,是所有規則裡**最脆**的一種。

理由:
- **沒有第二次機會**(值過了就沒了)。
- **沒有任何事後檢查抓得到漏掉的那次**——**漏掉長得跟「不適用」一模一樣**。
- 那條規則的作者本人,在對這件事警覺性最高的那一刻,都沒守住(第 2 點)。

## 結構解

守門與測試 runner 的機器可讀標記行本來就已經在印 `gate=… result=… scanned=N`,行尾再加一欄:

```
gate=boundaries result=PASS scanned=211 load=5.74
```

成本是一行 `os.loadavg()[0]`,**不依賴任何人記得**。

效果:
- 之後任何一次「這條為什麼那時候慢」的考古,答案就在當時那份輸出裡。
- 「有記 / 沒記」不再是**人的差異**,是**版本的差異**(某版之後全部有)。

## 可寫成一條的判準(比「要記 uptime」泛用)

> **易逝的觀測(load、可用記憶體、磁碟餘量、網路延遲、當下時間)由工具在產生輸出的
> 同一刻自動蓋章,不寫成給人遵守的規則。只有需要判斷的東西才交給人。**

## 跟過渡條款的關係(兩條合起來才完整)

**不取代** `self-diluting-mechanism.md` 檢查點 4 的過渡條款,只是把未來的缺口封死:

| | 做法 |
|---|---|
| 上線**之前**的觀測 | 標「規則生效前,無記錄」,**不准回填推測** |
| 上線**之後**的觀測 | **結構保證有記錄** |

> 過去誠實標空,未來結構保證。
