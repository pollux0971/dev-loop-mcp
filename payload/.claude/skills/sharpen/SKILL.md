# Sharpen:開工前把需求想清楚

改寫自 pstack 的 sharpen、in-your-own-words(MIT,見 `docs/dlm/THIRD-PARTY.md`)。

## 步驟

1. **重述**:用你自己的話寫兩三句:他想解決什麼問題、給誰用、做完他能做到什麼。不要照抄他的句子。
2. **專家會怎麼做**:這類東西做得最好的人會從哪裡開始、會先確認哪件事、用什麼方法證明做對了。
   寫成一兩條具體的做法(例:「先拿你上個月真的帳單跑一次,總額要跟銀行對得上」)。
3. **說太多或太少**:
   - 太少:做不出來或會做錯的空白(資料從哪來、錯了怎麼辦、算錢的規則)。
   - 太多:對目標沒幫助的限制,可以放寬。
   - 該由他決定的事留給他,不要替他選。
4. **一個驗證點**:這一版做完,用什麼可以觀察到的結果證明它對。這會變成整合點的 @e2e 場景。
5. 只問一個最重要的問題。他回答或說「對」之後,交給 `intake` skill。

## 回覆

照上面 1–4 各一小段,最後一個問題。總長控制在一個畫面內。不要寫「我理解你的需求是……」這種開場,直接重述。
